# ReputationOS — обзор для покупателя

Дата подготовки: 2026-07-28. Все цифры в этом документе сверены напрямую с продакшн-базой данных и кодом на дату подготовки, а не взяты из старых презентаций.

---

## Какую проблему решает

Малый и средний бизнес, а также маркетинговые/репутационные (SERM/ORM) агентства не имеют единого места, где видно, что о компании пишут на разных площадках (Яндекс Карты, 2ГИС, произвольные сайты-отзовики, Telegram-каналы и чаты). Мониторинг вручную занимает время, реакция на негатив запаздывает, а подготовка ответов на отзывы требует ресурса.

ReputationOS автоматически собирает упоминания и отзывы, классифицирует их (тональность, релевантность), формирует аналитику и помогает быстро сгенерировать черновик ответа с помощью AI.

## Для кого предназначен

- Малый и средний локальный бизнес (кафе, клиники, сервисы) — по тарифам FREE/START.
- Компании с несколькими точками/филиалами — тариф PRO.
- SERM/ORM-агентства, ведущие несколько клиентов одновременно — тариф AGENCY (до 100 компаний в одном воркспейсе).

## Основные функции

- Регистрация/вход, мультитенантность (Workspace), роли OWNER/ADMIN/MEMBER, приглашения по ссылке.
- Вход через Yandex ID (OAuth2).
- CRUD компаний и алиасов (альтернативных названий для поиска упоминаний).
- Автоматический синк отзывов и рейтингов по расписанию (BullMQ-очереди).
- Inbox с серверными фильтрами (платформа/статус/рейтинг/дата/классификация), разделение на «Упоминания» / «На проверку» / «Не по теме».
- Аналитика: динамика рейтинга, тональность, распределение по платформам.
- AI-черновики ответов на отзывы с пресетами тона (формальный/дружелюбный/краткий).
- Уведомления: Telegram-бот и Web Push при новых негативных отзывах (см. раздел «Известные ограничения» — не все заявленные типы уведомлений реализованы).
- Биллинг: тарифы, 7-дневный PRO-триал при регистрации, оплата через ЮKassa, серверная проверка лимитов (entitlements) на всех операциях создания.
- Админ-панель (SUPER_ADMIN): пользователи, воркспейсы, тарифы, аудит-лог, system-health (честно показывает статус интеграций, включая «не настроено», без фейкового «всё зелёное»).
- Резервное копирование PostgreSQL (ежедневно, автоматическая ротация 7 дней) и healthcheck каждые 5 минут.

## Источники мониторинга

| Источник | Метод | Статус |
|---|---|---|
| Яндекс Карты | Playwright-парсинг отзывов и рейтинга | Работает, основной источник |
| 2ГИС | Playwright-парсинг отзывов и рейтинга | Работает |
| WEB (произвольные страницы/сайты) | Собственный скрапер + LLM-классификация страницы | Работает, входит в PRO/AGENCY |
| Telegram (Scout) | MTProto-поиск по каналам/чатам, AI-классификация сообщений | Работает, но статус **BETA** — единственный общий Telegram-аккаунт обслуживает всех клиентов платформы одновременно (см. известные ограничения) |

## AI-функции

- Генерация черновика ответа на отзыв через YandexGPT (модель `yandexgpt-lite`, настраивается через ENV).
- Гибридный sentiment-анализ: по числовому рейтингу площадки + YandexGPT для неоднозначных WEB-упоминаний без явного рейтинга.
- AI-классификация Telegram-сообщений (релевантно / не по теме / спам / собственная реклама) с порогами уверенности, настраиваемыми через ENV.
- Абстракции AI-провайдера нет — YandexGPT интегрирован напрямую в двух местах кода. Замена на другого провайдера потребует доработки.

Модель: recurring-подписка, оплата через ЮKassa (кабинет и ключи требуют переоформления при передаче — см. `OWNER_DECISIONS.md`). Есть mock-провайдер только для разработки/тестов.

Billing policy после logic hardening: checkout всегда адресован явному `workspaceId`; управлять подпиской может только `OWNER` (не `ADMIN`/`MEMBER`). Upgrade начинается сразу после отдельной полной оплаты и открывает новый полный период; downgrade не отрезает уже оплаченный доступ и применяется на границе текущего периода. Продление того же плана добавляет 30/365 дней от действующей границы. Yearly checkout разрешён только при заданной положительной `priceYearly`; fallback на месячную цену отсутствует. После окончания оплаты данные сохраняются, а worker применяет актуальные FREE-entitlements перед каждым внешним запросом.

Аналитика периодов использует дату фактической публикации `publishedAt`. Записи без известной даты публикации исключаются из периодных KPI; рейтинг-тренд строится только из реальных `RatingSnapshot`.

Внимание: более ранние материалы (`PITCH.md`) содержат устаревшие цены (990/1990/3990 ₽) — таблица выше отражает то, что реально работает в проде сейчас.

## Текущее состояние проекта (на 2026-07-28, проверено напрямую)

- **Кодовая база**: ~39 000 строк TypeScript (по данным полного аудита от 27.07.2026), монорепо на pnpm workspaces + Turborepo, 5 приложений (`api`, `frontend`, `worker`, `landing`, `bot`) + 2 общих пакета. Строгий TypeScript везде, 0 TODO/FIXME в коде.
- **Prisma-миграций**: 25.
- **Тесты**: API 129/129 и worker 254/254 зелёные на 2026-08-16. Browser e2e требует установленных Playwright Chromium/WebKit binaries.
- **Живые данные в БД**: 68 воркспейсов, 68 пользователей, 4 компании, 1003 упоминания/отзыва, 3 активные подписки (2 через mock-провайдер — тестовые, 1 через реальный ЮKassa-платёж от 2026-06-29 — принадлежность и статус этого клиента требует уточнения у владельца, не подтверждена как действующий платящий клиент со стороны этого документа).
- **Безопасность**: в ходе аудита от 27.07.2026 были найдены и **закрыты** 2 критические уязвимости (подделка webhook ЮKassa, SSRF в WEB-мониторинге), а также ряд IDOR/auth-находок. Подробности — `REPUTATIONOS_SALE_AUDIT.md` и `REPUTATIONOS_SALE_FIX_REPORT.md` в корне репозитория.
- **Git**: logic hardening ведётся в `fix/logic-audit-hardening` от стабильной точки `66cb0c3`; ветка не push/merge в рамках аудита.
- **Продакшн**: развёрнут на общем VPS вместе с другими проектами владельца (не изолирован), см. `ARCHITECTURE_OVERVIEW.md` и `KNOWN_LIMITATIONS.md`.
- **Готовность к продаже**: по последнему внутреннему аудиту — 7/10 (было 4/10 до исправлений). Не готово: разделение инфраструктуры, переоформление юридических документов, полноценные refresh-токены, multi-account Telegram Scout.

Полная и более подробная версия анализа — в файлах `REPUTATIONOS_SALE_AUDIT.md` и `REPUTATIONOS_SALE_FIX_REPORT.md` в корне репозитория (не входят в упрощённый sale-package, но доступны для due diligence).
