## 4. Инфраструктура

| Актив | Статус | Комментарий |
|---|---|---|
| VPS (текущий сервер) | **[РЕШЕНИЕ ВЛАДЕЛЬЦА]** | На одном VPS с ReputationOS размещены ещё 3 несвязанных проекта владельца (`generationweb`, `growth-engine-web`, `growth-engine-worker`) плюс минимум 2 других сайта в nginx (`alfaflow`, `pismo-pervoklassniku`). Инфраструктура физически переплетена (PM2 + общий nginx). Передача VPS «как есть» невозможна без выделения ReputationOS на отдельный сервер, либо без прямого соглашения о судьбе чужих проектов на этом сервере |
| Docker-конфигурация БД/Redis (`docker-compose.yml`) | Готово к передаче | Часть кода, легко воспроизводима на новом сервере |
| PM2-конфиги (`ecosystem.worker.config.js`, `infra/pm2/...`) | Готово к передаче | Часть кода |
| Nginx-конфиг | Частично | Конфиг `reputation` (домен + API) в `/etc/nginx/sites-enabled/` изолирован; но **лендинг ReputationOS фактически обслуживается из чужого конфига `generationweb`**, что требует правки перед передачей |
| Скрипты backup/healthcheck (`infra/scripts/`) | Готово к передаче | Часть кода |

## 7. Что НЕ подтверждается и НЕ обещается этим документом

- Товарный знак «ReputationOS» — не проверялась регистрация как торговой марки; юридический вопрос, требующий отдельной консультации.
- Личные учётные записи владельца, использованные для регистрации интеграций (email, телефон для Telegram MTProto и т.д.) — не передаются как часть продукта, только их результат (API-ключи после переоформления).
- Другие проекты на VPS (GenerationWeb, Growth Engine, alfaflow, pismo-pervoklassniku) — не входят в продажу ReputationOS ни при каком варианте сделки.
- Клиентские данные в БД (68 воркспейсов, реальные пользователи) — их включение в сделку (передаются ли реальные пользователи как «действующий бизнес» или база должна быть очищена перед передачей) — **[РЕШЕНИЕ ВЛАДЕЛЬЦА]**, затрагивает вопросы согласия пользователей на передачу их данных новому оператору (152-ФЗ).
